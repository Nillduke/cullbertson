DATABASE IS THE CONTENT SOURCE
SQLite: database/database.sqlite. This is the Laravel content database.
It is not a live connection to the WordPress MySQL database.
149 content records include 92 posts, insurance pages and staff profiles.
Content is divided into ordered page_sections, stored as editable rich HTML.
Page URLs, titles, SEO descriptions, publication state, categories, featured
images and presentation settings are database fields. There is no live page
manifest or static article catalog. CSS, JavaScript and image binaries remain
normal public assets; their references and editorial content are stored in DB.

Shared header/menus, footer, feedback drawer, exit popup and 404 content are
site_blocks. Form options, service questions, shared copy and homepage quote
product content are form_definitions. Quote requests and feedback are stored
in quote_requests and feedback_entries. Media metadata is in media_assets.

ADMIN CONTENT WORKFLOW
Pages & posts: search, create, edit, reorder sections, draft/publish and set SEO.
Edit visually: opens an isolated rich-text section editor with formatting,
link/image tools. HTML is also available for layout edits. Click Save content
to write the database. Stored content is rendered as HTML, never executed as Blade.
Header & footer: edit shared blocks, including menus and popup copy.
Forms: edit database questions, choices and labels; retain existing field IDs.
Media: upload JPEG, PNG or WebP (up to 5 MB) and use its path in an editor.
Inbox: inspect private requests/feedback and update quote-request status.
There is no public registration. Admin routes require authenticated admin users.

AUTOMATIC CONTENT
The blog index queries published posts with pagination. The homepage article
feed and insurance sliders query published posts, with relevant categories
first in insurance sliders. New published posts appear automatically. Drafts
and future-dated records are hidden. Existing navigation is managed in the
shared header/footer blocks; a new page is available at its saved URL.

FOR DEVELOPERS
Routes: routes/web.php. Models: app/Models/. Frontend: content/page.blade.php.
PageController queries Eloquent records and ContentRenderer renders sections.
The shared layout queries database blocks. No per-page Blade views are used.
Form clients load /forms/auto-options and /forms/services from the database.
The old public options/services JSON files have been removed from public/.

INSTALLATION IMPORT SOURCES
The original approved design is archived under database/import/ solely for
initial seeding and recovery. Runtime controllers do not read these files.
On an empty database: php artisan migrate, then
php artisan db:seed --class=ContentSeeder
php artisan cms:create-admin
The import refuses to overwrite existing content. Do not run migrate:fresh on
a database containing edits. The former static builder is retired and guarded.
